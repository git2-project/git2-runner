# Runner version notes — 2026-10-29

**Audience:** every git2 lane (Dash, console, codeplane, deploy) and their coding agents.
**Scope:** The CI lane's first contract and its first working code. `ci.v1` (five proto files) is ready for review, `.git2-ci.yml` v0 has a spec and a JSON schema, the `ci_svc` schema is a migration on a git2 branch, and ci-svc plus `git2-runner` run a two-stage pipeline in real containers end to end.

**Canonical reference:** [docs/api/](../../../api/README.md), starting with [overview.md](../../../api/overview.md). The proto files are in [app/proto/ci/v1/](../../../../app/proto/ci/v1/).
The API docs are the source of truth; this note only summarizes the change.

**Breaking?** No. This is the first version; nothing existed to break.

---

## In one minute

- **ci-svc** is the CI service. It speaks gRPC on two ports: **internal `:9090`** for git2 services (pipelines, runner admin, secrets) and **runner `:9091`** for build hosts.
- **Like git-svc, ci-svc trusts its callers on the internal port.** dash-api and admin-api check the user's permissions first.
- **A push starts a pipeline** when someone calls `TriggerPipeline` with the push event's ID as the idempotency key. Jobs run stage by stage in containers on runners. Logs stream back live; secrets are injected and masked.
- **Postgres is the queue** (`ci_svc.jobs`, leased with `FOR UPDATE SKIP LOCKED`); the shared Redis only wakes waiting runners and log viewers. Losing Redis costs seconds, never data.
- **Events** `ci.v1.PipelineCreated`, `ci.v1.PipelineFinished` and `ci.v1.JobFinished` go to `ci_svc.outbox` in the same format as `git_svc.outbox`.
- **What works today**, tested: all RPCs below, against PostgreSQL directly and in pooler mode, and a real runner running jobs in Docker. **What does not yet:** reading `.git2-ci.yml` from git-svc (needs codeplane's `CommitService`), job source checkout, retry, artifacts.

## 🟢 NEW — `ci.v1.PipelineService` (for Dash and the push relay)

On the internal port. Full reference: [pipelines.md](../../../api/pipelines.md).

| RPC | What it does | Errors |
|---|---|---|
| `TriggerPipeline` | Starts a pipeline for (repository, ref, commit). **Idempotent on `idempotency_key`**; a second call returns the same pipeline with `created = false` | `INVALID_ARGUMENT`, `NOT_FOUND` (no `.git2-ci.yml`), `ALREADY_EXISTS` (key reused for other data), `UNAVAILABLE` |
| `GetPipeline` | One pipeline with its jobs grouped by stage | `INVALID_ARGUMENT`, `NOT_FOUND` |
| `ListPipelines` | A repository's pipelines, newest first, optional `ref` filter, AIP-158 pages (default 20) | `INVALID_ARGUMENT` |
| `CancelPipeline` | Cancels waiting jobs at once, running ones within ~15 s; no-op on a finished pipeline | `INVALID_ARGUMENT`, `NOT_FOUND` |
| `GetJob` | One job | `INVALID_ARGUMENT`, `NOT_FOUND` |
| `StreamJobLog` | Log bytes from an `offset`; with `follow`, live until the job ends | `INVALID_ARGUMENT`, `NOT_FOUND` |
| `ValidateConfig` | Checks a `.git2-ci.yml`; returns every error with path, line and column | `INVALID_ARGUMENT` (> 256 KiB) |

**Statuses.** Pipelines: `PENDING`, `RUNNING`, `SUCCESS`, `FAILED`, `CANCELED`. Jobs add `CREATED` (waiting for an earlier stage) and `SKIPPED` (an earlier stage failed). Failure reasons: `SCRIPT_FAILURE` (with `exit_code`), `TIMEOUT`, `RUNNER_LOST`, `IMAGE_PULL_FAILURE`, `RUNNER_SYSTEM_FAILURE`.

**An invalid `.git2-ci.yml` still makes a pipeline:** status `FAILED`, no jobs, and `error_message` like `.git2-ci.yml is invalid: line 4: build.scrpt: unknown key; …`. Show it next to the commit.

```go
import civ1 "github.com/git2-project/git2-runner/app/gen/go/ci/v1"

pipelines := civ1.NewPipelineServiceClient(conn) // ci-svc:9090
list, err := pipelines.ListPipelines(ctx, &civ1.ListPipelinesRequest{RepositoryId: repoID, Ref: "refs/heads/main"})

stream, err := pipelines.StreamJobLog(ctx, &civ1.StreamJobLogRequest{JobId: jobID, Follow: true})
for {
	msg, err := stream.Recv()
	if errors.Is(err, io.EOF) { break } // the job ended and every byte was sent → SSE "event: end"
	if err != nil { break }             // reconnect later with offset = last offset + len(last data)
	writeSSE(msg.GetData())
}
```

`go get github.com/git2-project/git2-runner/app@<commit>` until the first tag (`app/v0.1.0`) is cut after this is merged.

## 🟢 NEW — `ci.v1.RunnerAdminService` (for the console)

On the internal port. Full reference: [runners.md](../../../api/runners.md).

| RPC | What it does |
|---|---|
| `CreateRegistrationToken` | A one-time token (`g2rt_…`, default 1 h, up to 7 days). **Shown once**; ci-svc keeps only a hash |
| `ListRunners`, `GetRunner` | Runners with `status` `ONLINE` (seen in the last 90 s), `OFFLINE` or `PAUSED`, labels, version, platform, last seen |
| `UpdateRunner` | Pause/resume (`paused`), change `description`. Only fields that are set change |
| `DeleteRunner` | Its token stops at once; its running job fails as `RUNNER_LOST` within a minute |

The runner side: `git2-runner register -url https://<instance>:9091 -token <token> -labels linux,docker`, then `git2-runner run`.

## 🟢 NEW — `ci.v1.SecretService` (for the console and Dash)

On the internal port. Full reference: [secrets.md](../../../api/secrets.md).

- `SetSecret` (create or replace), `ListSecrets` (names and dates, **never values**), `DeleteSecret`.
- Scopes: `SECRET_SCOPE_INSTANCE` (`scope_id` empty) and `SECRET_SCOPE_REPOSITORY` (`scope_id` = repository ID). The repository wins on equal names.
- Names: `A-Z 0-9 _`, not starting with a digit, `CI_` or `GIT2_`. Values: up to 32 KiB, multi-line allowed.
- Encrypted at rest with `GIT2_CI_SECRETS_KEY`; masked as `[MASKED]` in job logs.

## 🟢 NEW — Events in `ci_svc.outbox`

Same columns and encoding as `git_svc.outbox`. Full reference: [events.md](../../../api/events.md).

| Event | When | Typical consumer |
|---|---|---|
| `ci.v1.PipelineCreated` | A pipeline is created | activity feeds |
| `ci.v1.PipelineFinished` | Once, at `SUCCESS`, `FAILED` or `CANCELED` | **Dash: ✓/✗ on commits and merge requests**, "pipeline failed" notifications |
| `ci.v1.JobFinished` | Once per job, `SKIPPED` included | job-level views |

Delivery is at least once: drop duplicates by `event_id`.

## 🟢 NEW — `.git2-ci.yml` v0 and its JSON schema (WBS-10.1)

Full reference: [ci-yaml.md](../../../api/ci-yaml.md). Schema: [git2-ci.schema.json](../../../../app/internal/ciyaml/git2-ci.schema.json).

```yaml
stages: [build, test]
variables:
  CGO_ENABLED: "0"
build:
  stage: build
  image: golang:1.26
  script:
    - go build ./...
test:
  stage: test
  image: golang:1.26
  tags: [linux]
  timeout: 10m
  script: go test ./...
```

Keys: `stages`, `variables`, and per job `stage`, `image`, `script`, `variables`, `tags`, `timeout`, `artifacts` and `cache` (both accepted, used from W6/W8). Anchors and `<<:` merge keys work; keys starting with `.` are templates. GitLab keys we don't support (`rules`, `needs`, `services`, …) are rejected by name, never silently ignored. Every job gets `CI_PIPELINE_ID`, `CI_JOB_ID`, `CI_COMMIT_SHA`, `CI_COMMIT_REF_NAME`, `CI_COMMIT_BRANCH`/`CI_COMMIT_TAG` and friends.

**v0 jobs start in an empty `/workspace`**: source checkout comes with codeplane's archive RPC (A-04).

## 🟢 NEW — The `ci_svc` schema (a migration in git2)

`migrations/003_ci_pipelines.sql`, on the git2 branch `feat/ci-svc-schema` (from `dev/main`), together with `contracts/ci/README.md`, which points to our proto like `contracts/git/` does for codeplane. Tables: `runners`, `registration_tokens`, `pipelines`, `jobs`, `job_log_chunks`, `secrets`, `outbox`. All statements are idempotent, and the file applies cleanly twice. git2-runner keeps a byte-identical copy in `migrations/` for its tests, as codeplane does.

## ℹ️ FYI — Decisions behind this

| ADR | Decision |
|---|---|
| [0006](../../../decisions/0006-job-queue-and-lifecycle.md) | The job queue is a Postgres table, not a broker: leases with `SKIP LOCKED`, 60 s lease, 15 s heartbeat, a reaper for lost runners (this is also what recovers a restore taken mid-run) |
| [0007](../../../decisions/0007-ci-secrets-live-in-ci-svc.md) | CI secrets live in ci-svc, not in git2 or auth-svc: ci-svc is their only reader, at the moment it hands a job to a runner |
| [0008](../../../decisions/0008-runner-uses-the-docker-engine-api.md) | The runner uses the Docker Engine API: secrets never reach a command line or a file, and jobs are unprivileged with resource limits |
| [0009](../../../decisions/0009-schema-copy-tooling-and-tests.md) | Same schema-copy, tooling (`tools.mod`) and test setup as codeplane |
