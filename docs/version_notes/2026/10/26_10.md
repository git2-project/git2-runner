## 🟡 CHANGED — ci-svc is confirmed in git2-runner

Yesterday's note said "planned". It is now decided ([ADR 0001](../../../decisions/0001-ci-svc-lives-in-git2-runner.md)). ci-svc keeps its name, its schema is `ci_svc` (migrations still go into git2), and its gRPC package is `ci.v1`. git2's README still lists `ci-svc/` as a directory of git2; that row should point here.

## 🟢 NEW — One Redis, shared by all services

The instance runs one Redis for every git2 service. It is not backed up, so no service may keep data there that a restore needs.

How the CI lane uses it ([ADR 0003](../../../decisions/0003-postgres-truth-shared-redis-signals.md)):

| Key or channel | What it holds |
|---|---|
| `ci:jobs:wake` (channel) | Wakes runners that are waiting for a job |
| `ci:log:<job_id>` (channel) | New log lines, for viewers connected to another ci-svc replica |
| `ci:rl:<action>:<key>` | Rate-limit counters |

- Postgres stays the source of truth for jobs, the queue and logs. If Redis is lost, ci-svc gets slower, never wrong.
- Only ci-svc connects to Redis. Runners on build hosts never do.
- Every key and channel we use starts with `ci:`. Please do the same with your service's name.
