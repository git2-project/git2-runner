## 🟡 CHANGED — events are pushed to an `EventSink`

Agreed with codeplane on git2-runner #33:

| | Before (31 Oct) | Now |
|---|---|---|
| How events leave an outbox | to be agreed | Each producer's relay calls `events.v1.EventSink.Deliver` on every subscriber of that event type, and marks the row published when all answered `OK` |
| Where the contract lives | — | `events.v1` in git2-codeplane (`proto/events/v1/`), with a pointer in git2's `contracts/events/` |
| Who turns a push into pipelines | "whoever delivers the event" calls `TriggerPipeline` | **ci-svc itself.** It records `git.v1.RepositoryPushed` in `ci_svc.inbox`, then starts one pipeline per updated ref (`"<event_id>:<ref>"`). Nobody calls `TriggerPipeline` for pushes |
| `TriggerPipeline` | pushes and manual runs | manual runs (dash-api) and development |

What a consumer's answer means (each call has a 10 s deadline):

| Answer | The relay |
|---|---|
| `OK` (stored, or seen before) | marks the event delivered |
| `INVALID_ARGUMENT`, `FAILED_PRECONDITION` | logs at ERROR and marks it delivered |
| any other code, including `UNKNOWN` and `UNIMPLEMENTED` | retries with backoff, never drops |

`UNIMPLEMENTED` is retried because gRPC also answers it when a consumer does not serve `EventSink` yet, as ci-svc until #20. A consumer that gets a type it does not handle answers `INVALID_ARGUMENT`. When one subscriber must be retried, every subscriber of that type gets the event again, and drops the repeat by `event_id`.

`Deliver` only stores the event and answers; the work happens afterwards. Delivery stays at least once, so drop duplicates by `event_id`.

## ℹ️ FYI — A-03 confirmed

ci-svc will read `.git2-ci.yml` with `CommitService.GetBlob` from git2-codeplane `v0.2.0`, with `ref` set to the pushed commit's full SHA ([assumptions.md → A-03](../../../design/assumptions.md#a-03--reading-git2-ciyml-at-a-commit)).

## ℹ️ FYI — retrying a pipeline

Retrying a whole pipeline needs no new RPC: call `TriggerPipeline` with the old pipeline's `repository_id`, `ref` and `commit_sha`, `PIPELINE_TRIGGER_MANUAL` and a new `idempotency_key` ([pipelines.md → Retrying](../../../api/pipelines.md#retrying)). A job-level `RetryJob`, which keeps the earlier attempt's log, comes in W4.

## ℹ️ FYI — a correction

The one-schema-per-service rule comes from git2's `CLAUDE.md` and `README.md`. Earlier notes and docs here cited codeplane ADR 0006, which only says that git-svc owns `git_svc`.
