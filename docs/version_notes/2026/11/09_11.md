# Runner version notes — 2026-11-09

**Audience:** Deploy (Ceyda), Dash (Bilge), Codeplane (Apo) and their coding agents.
**Scope:** ci-svc now reads `.git2-ci.yml` from git-svc, so it needs git-svc's address. A file that exists but cannot be a pipeline now gives a failed pipeline with a reason.

**Canonical reference:** [docs/api/config.md](../../../api/config.md) and [docs/api/pipelines.md → TriggerPipeline](../../../api/pipelines.md#triggerpipeline).
The API docs are the source of truth; this note only summarizes the change.

**Breaking?** No. Without the new variable ci-svc behaves as before: triggers answer `UNAVAILABLE`.

---

## 🟢 NEW — `GIT_SVC_GRPC_ADDR`

ci-svc reads `.git2-ci.yml` at the pushed commit with git-svc's `CommitService.GetBlob` (git2-codeplane `v0.2.0`, assumption A-03).

```yaml
# compose: the ci-svc service, once it is in the stack
environment:
  GIT_SVC_GRPC_ADDR: git-svc:9090   # the same name and value as the gateway's
```

- Empty: pushes cannot start pipelines, and ci-svc logs a warning at startup.
- `GIT_SVC_GRPC_ADDR` and `GIT2_CISVC_DEV_CONFIG_DIR` together: ci-svc refuses to start.
- git-svc down: ci-svc keeps running; a trigger answers `UNAVAILABLE` and is retried.

## 🟢 NEW — failed pipelines for unusable files

A `.git2-ci.yml` that git-svc returns but that cannot be a pipeline now gives a `FAILED` pipeline, as a YAML error already does. `error_message` is `.git2-ci.yml is invalid: ` followed by:

| Case | Reason |
|---|---|
| a directory or submodule called `.git2-ci.yml` | `it is not a regular file` |
| a symbolic link | `it is a symbolic link` |
| a Git LFS pointer | `it is stored in Git LFS` |
| binary content | `it is a binary file` |
| over 256 KiB | `the file is larger than 256 KiB` |
